## 01 Overall Architecture

| Decision | Reason | Source |
| --- | --- | --- |
| Class list is Main / Repository / Commit / StagingArea; Utils is edge utility | Command logic centralized in Repository; data layer only object structure | 01:6-22 |
| Blob is not a class | blob is just disk byte file; filename → blob ID maintained by Commit (see 02) | 01:30 (responsibility table); 02:7-9 |
| StagingArea is a class but only data class: holds addition/removal two entry groups (package-private final fields, Repository operates directly); staging rules belong to Repository | Consistent with all finalized command cards (Repository directly operates two collections); 2026-10-26 changed 01:29 responsibility table, original "execute staging rules" moved to Repository | 01:29 (responsibility table, changed) |

| Command methods receive only operands, same name as command, hyphen to camelCase; init no args | Method naming unified, no command name | 01:71-73 |
| Dependency strictly top-down Main → Repository → data layer, no reverse/cycle | Clear layering; Utils does not depend on business classes | 01:35-50 |

## 02 Object Model

| Decision | Reason | Source |
| --- | --- | --- |
| Blob no Java class, in memory just byte[], no filename/path | Filename ↔ blob mapping maintained by Commit map | 02:7-8 |
| Blob ID = SHA-1(raw bytes), same content shares one blob | Content addressing, no duplicate storage | 02:9,100-104 |
| Commit five fields: message/timestamp/firstParent/secondParent/filenameToBlob | Full snapshot; parent three types (initial/normal/merge) | 02:17-31 |
| Commit stores full snapshot not diff, immutable after construction | Snapshot model, fields do not change | 02:34-35 |
| StagingArea two groups: addition Map<name,blobID>, removal Set<name>; cleared after commit success | Records updates relative to current commit | 02:43-51 |
| Remote map = remote name → remote .gitlet path; only whole add/delete, cannot change value | Logical data shape, mutable | 02:58-70 |
| fetch produces [remote]/[branch], reuses branch model, name contains /, different dir | Remote tracking branch no separate model | 02:67 |
| Branch = one file one pointer under refs/heads/; HEAD is branch name string, only refers to branch never commit | current commit looked up via HEAD → branch file → ID | 02:76-80 |
| Collection choices HashMap (Commit/Remote maps), TreeMap/TreeSet (status ordered listing scenarios) | Ordered collections self-order, output no manual sort | 02:88-96 |
| SHA-1: type tag first arg + all fields fixed order; map sorted per argument, null → ""; time as milliseconds | Any field change changes ID; parameterized not raw concat | 02:100-123 |

## 04 Error Handling (finalized)

| Decision | Reason | Source |
| --- | --- | --- |
| All error messages centralized as list, split local/remote; body list presentation (no wide table) | Command cards uniformly reference back, verbatim message single source; long message list does not stretch table | 04:5-96 |
| Unified reporting chain: throw Utils.error(...) → run catch → Utils.message → System.exit(0) | Utils.error only creates exception not throw; single print exit ensures verbatim; unchecked exception penetrates layers | 04:124-143 |

| log, global-log, status no failure cases | spec these three have no Failure cases | 04 (end of section 1) |
| Remote 5 sentences: remote exists/not exists, pull down before pushing, remote directory not found, that remote does not have that branch; pull no dedicated message | pull failure = fetch+merge union (spec:1073) | 04:72-96 |
| Failure atomicity: check → in-memory compute → write; all throws before first write; write add-only new objects first, then branch pointer, finally clear stage | Pointer not moved visible state unchanged; clear stage before pointer loses add changes | 04:144-168 |
| Five protected scopes: working directory, staging area, .gitlet, branch pointer, HEAD; read-only commands naturally atomic; dangerous commands rm/checkout/reset/merge | spec requires zero change on failure, names dangerous commands (spec:166-167,193) | 04:148-172 |
